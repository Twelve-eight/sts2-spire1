## 3. CardRarityOdds / N'loth's Gift

`CardRarityOdds : AbstractOdds` (`.tmp/dllsrc/MegaCrit.Sts2.Core.Odds/CardRarityOdds.cs:11`). Three public roll methods: `Roll(CardRarityOddsType)` (`:69-81`), which delegates to `RollWithoutChangingFutureOdds(type, type == BossEncounter ? 0f : CurrentValue)` (`:71`) and then does the pity bookkeeping — reset `CurrentValue = -0.05f` on a Rare, else `Min(CurrentValue + RarityGrowth, 0.4f)` (`:72-79`); `RollWithoutChangingFutureOdds(CardRarityOddsType type, float offset)` (`:96-111`), which is **public** and adds `offset` straight onto the rare probability (`num2 = GetBaseOdds(type, Rare) + offset`, `:99`, tested at `:102`); and `RollWithBaseOdds(CardRarityOddsType)` (`:120-134`), which ignores `CurrentValue` entirely.

**The precision check.** `CardFactory.RollForRarity(Player, CardRarityOddsType rollMethod, CardCreationSource source, HashSet<CardRarity>, bool forceRarityOddsChange)` (`.tmp/dllsrc/MegaCrit.Sts2.Core.Factories/CardFactory.cs:244-261`) computes `flag2 = forceRarityOddsChange || (source == CardCreationSource.Encounter && (uint)(rollMethod - 1) <= 2u)` (`:246-257`) — that unsigned range test is exactly `rollMethod ∈ {RegularEncounter, EliteEncounter, BossEncounter}` per `.tmp/dllsrc/MegaCrit.Sts2.Core.Runs/CardRarityOddsType.cs:3`. Then `:259`: `rarity = (!flag2) ? RollWithBaseOdds(rollMethod) : Roll(rollMethod)`. So **combat rewards call `Roll(rollMethod)`**, reached from `CreateForReward` (`:214`) via `:228`. Shops are a different call site entirely — `Hook.ModifyMerchantCardRarity(..., player.PlayerOdds.CardRarity.RollWithoutChangingFutureOdds(CardRarityOddsType.Shop))` at `CardFactory.cs:50` — and non-encounter sources fall to `RollWithBaseOdds`.

**Verdict: the relic is implementable.** A Harmony prefix on the public instance method `CardRarityOdds.Roll(CardRarityOddsType)` hits combat rewards and only combat rewards. The earlier "impossible" verdict rested on the observation that `Roll` overwrites the pity offset — true, but irrelevant to a prefix, which *replaces* the roll rather than seeding it. The prefix can call the public `RollWithoutChangingFutureOdds(type, offset)` with an offset chosen so the rare probability triples, then reproduce the eight lines of pity bookkeeping itself. Concretely, vanilla effective rare chance is `base + CurrentValue` where `base = GetBaseOdds(type, Rare)`; for ×3 pass `offset = 2*base + 3*CurrentValue`, then apply `:72-79`. The base values are reachable as public statics on the same class: `RegularRareOdds` (`:33`, 0.03 / 0.0149 under Scarcity), `EliteRareOdds` (`:37`), `ShopRareOdds` (`:41`), `RarityGrowth` (`:31`), with `_baseRarityOffset = -0.05f` (`:27`) and `_maxRarityOffset = 0.4f` (`:29`). Cost: one prefix, a guard that some player in the run owns `NlothsGift`, and re-implementing that pity update. A secondary lever exists but is not needed — `public static float regularCommonOdds` (`:13`) is a writable static field, though rare odds is a get-only property.

BaseLib itself offers **no** rarity hook: the entire BaseLib tree has zero references to `RollForRarity`, `PlayerOdds`, or `CardRarity.Roll`; `CardRarity` appears only as a constructor parameter (`Abstracts/CustomCardModel.cs:20`, `Abstracts/ConstructedCardModel.cs:16`) and `CardRarityOddsType` only as serialisation plumbing in `Patches/Fixes/CardRewardSerializationPatches.cs:109,122,313,341`. What BaseLib *does* supply is the patch tooling: `Extensions/HarmonyExtensions.cs:14` `TryPatchAll(this Harmony, Assembly, string? category)`, plus `Utils/Patching/{InstructionPatcher, CallMatcher, InstructionMatcher, OpCodeValues, AsyncMethodCall}` and the IL-emit helpers `CodeInstructionExtensions.TryGetIntValue` (`:12`), `MethodInfoExtensions.Call`/`CallVirt` (`:18,22`), `FieldInfoExtensions.Stfld`/`Ldfld`/`Ldflda` (`:9,13,17`). **Reclassify gap 4 from "unimplementable" to "one prefix, no BaseLib hook needed."**

## Net effect on the gap list

M2 monsters/encounters is **not** blocked by BaseLib — the surface is complete in shipped v3.3.5 and one PNG per monster suffices. Character visuals are **not** blocked either, and `PlaceholderCharacterModel`'s all-virtual members allow a one-property-at-a-time migration. `NlothsGift` moves from impossible to a single Harmony prefix on `CardRarityOdds.Roll`. `Girya`'s live FLAG closes with a `TryModifyRestSiteOptions` override plus a `CustomRestSiteOption` subclass — no library support at all. `MutagenicStrength` closes with `CustomTemporaryPowerModelWrapper` plus `InvertInternalPowerAmount`, which we already depend on. ## Tooling
